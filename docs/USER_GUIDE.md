# SEAL Hackathon User & Role Workflow Guide

This guide details the operational workflows for all user roles supported by the **SEAL Hackathon Management System**.

---

## 👤 User Roles

1. **Student / Participant**
2. **Team Leader**
3. **Mentor**
4. **Judge**
5. **Staff / Coordinator**
6. **Administrator**

---

## 📋 Role Workflows

### 1. Student Workflow
- **Registration**: Register an account with an official FPT or partner university email address.
- **Team Discovery**:
  - Visit **Team Explorer** to view teams currently looking for members.
  - Send join requests to public teams or enter a security PIN for private teams.
- **My Event View**: Access your active team dashboard to communicate with teammates and view competition tracks.

### 2. Team Leader Workflow
- **Team Creation**: Create a new team for a specific event and track. Set team visibility (Public vs Private PIN).
- **Member Management**: Approve/reject pending join requests, assign member roles, or disband the squad if necessary.
- **Submission Management**: Access the **Submission** page to upload project repository links, demo URLs, and documentation before the specified round deadline.

### 3. Mentor Workflow
- **Assigned Teams**: View assigned teams for each hackathon season.
- **Chat & Guidance**: Communicate with team members via real-time WebSocket chat under the **Team Chat** section to provide technical feedback and guidance.

### 4. Judge Workflow
- **Grading Matrix**: View allocated evaluation rubrics and submission links.
- **Scoring**: Input rubric scores and qualitative feedback per criteria. Every score change is automatically recorded in the audit log for complete evaluation transparency.

### 5. Coordinator / Admin Workflow
- **Event Lifecycle**: Setup hackathon seasons, registration dates, tracks, and matrix round structures.
- **Monitoring & Audit**: Monitor real-time leaderboards, manage user roles, review audit logs, and trigger backup/restore operations.
